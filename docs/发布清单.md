## 将来的人工推送步骤（本次不执行）

1. 公开前复审全部历史和授权；由用户创建 GitHub 空仓库，设置远程地址并按实际分支推送，确认 Actions Ubuntu/Windows 矩阵与可选 R 对照作业的真实执行结果。报告中的理论零差异仍需统计负责人复核。

3. 所有组织发布门槛满足后，由维护者按组织策略签名或创建 `v0.1.0` 标签、推送标签并创建 Release，附经确认的构建产物和 SHA-256。
4. 如决定发布 PyPI，核实名称和权限、配置可信发布或专用令牌，先测试仓库，最后由授权人发布正式仓库。

本施工不创建远程、不推送、不上传。清单哈希本身不是数字签名，公开前仍需人工保密复核。
